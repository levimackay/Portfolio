Python · Ollama · Shipped

Lydia

A coding agent that runs entirely on your own machine. It reads your code, edits files, runs commands, drives git, and checks its own work by running your tests, all through a local Ollama model. No API key, no account, and nothing leaves the machine.

Its implementation was written with heavy AI assistance and the README says so plainly. What is mine is the architecture, the tool surface and its safety model, the decision to stay local only, and the review of everything that lands. Two of the merged pull requests came from people I have never met, and every change has to pass the suites on Python 3.11 through 3.13 before it goes in.

Challenge
The useful coding agents are metered, need an account, and send your code to somebody else's server. The tradeoff is real: a local model is smaller and slower, so the design has to earn its keep on the routine work.
Approach
An agent loop over a small tool surface, one diff per approval rather than whole-file rewrites, and the model checks itself by running the project's own tests and reading the failure.
Current state
On PyPI, 36 stars and 8 forks, 475 tests across 56 files running green in CI, and two merged pull requests from outside contributors.

C · Compiler · Phase 3 next

izvor

A language and compiler I'm writing from scratch in C: a hand-written lexer, a recursive-descent parser, and a syntax tree, compiling to C in 12 phases. The window is a recorded session showing the lexer, the parser, and today's evaluator running on real input, including a parse error.

Challenge
Understanding a compiler by building one: source text to tokens, tokens to a tree, a tree to generated C.
Approach
A 12-phase plan from lexer to a native binary, tested with plain asserts and CI on Linux and macOS under UndefinedBehaviorSanitizer.
Current state
Phases 1 and 2 are done: the lexer and the parser. Phase 3, variables and statements, is next.
