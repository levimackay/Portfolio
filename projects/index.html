C · Compilers · In progress

tinylang

A programming language built from scratch in C: a lexer, a recursive-descent parser, and a tree-walking interpreter, then a bytecode compiler and a stack VM to replace the back half the way real languages do it.

I'm working through it by hand, task by task — every task is done when its test passes. The window on this panel is the real output of make p0-02, the task that went green this week.

Challenge
Understanding a language implementation by building one, not reading about one: source text to tokens, tokens to AST, AST to a value.
Approach
An 8-phase roadmap from C fundamentals through a stack-based VM, roughly 70–90 hours of work, each task shipped with an assert-based test. Compiled with -Wall -Wextra -fsanitize=undefined from the first file.
Current state
Phase 0 in progress. Task 0.2 (variables and arithmetic) is green; the transcript shown is genuine, unedited output.

C · Systems · Planned build

minidb

A single-file database engine built by hand in C: binary file formats, a pager with fixed-size pages, B-trees, cursors, and a small SQL parser over the top.

The full roadmap and Phase 0 scaffolding are written and committed; my own implementation hasn't started yet. The panel shows the actual roadmap, because that's what exists — there is no REPL to screenshot, so I'm not showing one.

Challenge
Knowing what a database actually does under the query layer: how rows become bytes, how bytes become pages, how a B-tree makes lookup logarithmic.
Approach
Eight phases from binary file I/O to a write-ahead log, ~43–65 hours, phases 0–1 fully scaffolded with stubs, tests, and a reference. Sequenced after tinylang, which covers the C this project assumes.
Current state
Roadmap and scaffolding committed; implementation not started. That is what "planned build" means here.

Swift · SwiftUI · Early

TaHelper

A native SwiftUI dashboard for teaching assistants: it pulls a course's enrolled students from the Canvas LMS API and lists them sorted by an at-risk score, with High/Medium/Low badges, current grade, and missing and late assignment counts.

The SwiftUI code is real and early. It has never run against a live Canvas course — the grade and assignment fields are placeholder-computed until the real endpoints are wired — so a screenshot today would show numbers that mean nothing, and I'd rather show you the shape of the thing than fake the data.

Challenge
A TA scanning a full course roster can't see who's slipping until the gradebook already shows it. The roster should arrive pre-sorted by who needs attention.
Approach
Canvas API enrollment data feeding a per-student at-risk score that orders the list, rendered natively in SwiftUI rather than another web dashboard.
Current state
Early-stage code, not yet integrated with live course data. Next milestone: real grade and assignment endpoints replacing the placeholder computation.

Swift 6 · iOS 26 · Phase 0

FORGE

A native iOS personal development system that turns long-term goals into adaptive daily missions: you complete a mission, your skill progress updates, and the next recommendation gets better.

Phase 0 is complete — product definition, architecture, decision records, design language, and roadmap, written so a stranger could explain what version 1 will and won't contain. There is no app UI yet, and this panel doesn't pretend otherwise: what you're looking at is the core loop the whole architecture is built around.

Challenge
Long-term goals fail at the daily level: nothing translates "where I want to be in two years" into "what I should do today."
Approach
A closed loop — Goal → Skills → Progress → Recommended Mission → Completion → Updated Progress → Better Recommendations — with a deterministic scoring function that can justify each recommendation in a sentence. Swift 6, strict concurrency from the first commit.
Current state
Phase 0 (foundation) complete; Phase 1 (the smallest thing that closes the loop, one device, no network) is next. Speed is explicitly not a goal.
