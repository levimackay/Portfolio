What it is

I built Lydia to work on a codebase from the terminal using local models. It can read files and propose edits, then run commands such as a project’s test command. The local client talks to Ollama over HTTP. That needs no account and no API key. The model produces tool requests, and Python code carries them out.

It is open source, and two developers who found it on their own sent pull requests that I reviewed and merged. One added scheduled briefings through a Linux user service. The other fixed boolean configuration values that were being stored as strings.

How it works

The conversation loop passes the message history and tool schemas to a model client. A response can contain text or tool calls. The loop looks up each requested tool by name, executes its handler, and appends the result to the conversation. It then asks the model to continue with that result available. A response without tool calls ends the turn.

The loop accepts callbacks for streaming text and displaying tool activity. Its execution logic does not depend on the terminal renderer. Unknown tools produce an error result, as do filesystem errors, so the model can see that an operation failed. There is also an iteration limit that ends a turn if tool calls keep arriving without a final response.

The hard part

I put path resolution in src/lydia/tools/paths.py because a requested filename cannot be trusted as a location. A path containing parent directory segments can leave the project. Checking its written prefix is insufficient because resolving the path can change where it points. The helper resolves the candidate and the project root before checking containment.

def resolve_within(root: Path, relative: str) -> Path:
    """Resolve *relative* against *root*, raising if it escapes the root."""
    candidate = (root / relative).resolve()
    try:
        candidate.relative_to(root.resolve())
    except ValueError:
        raise PathEscapesProjectError(relative) from None
    return candidate

resolve_within uses Path.relative_to to check that the resolved candidate belongs under the resolved root. It raises PathEscapesProjectError when that check fails. tests/test_paths.py covers parent traversal and absolute paths outside the project, alongside accepted relative paths. This is a boundary for filesystem tools. Shell commands run through subprocess with a working directory and timeout; that working directory is not an operating system sandbox.

Where it stands

The source is public. Local is the default: with no extra configuration Lydia talks to Ollama on the same machine and nothing else. Two modes that you have to turn on do send requests elsewhere, a remote Lydia server and a Gemini client that uses your own key. The 413 tests are counted from the test files. The shell tool runs commands with a timeout in the project directory and reports the output and exit status. It is not a sandbox.
