01

What it is

Proven Blue is a team project: verified work portfolios for people in the trades.

  • Someone posts the work they did, a verified contractor or teacher confirms it, and they can share the portfolio through a link.
  • I built the backend and its security.
  • The screenshots here are the public landing page. My work sits behind it.
Read the rest

My part includes the API and the database rules behind it. Shared portfolio routes decide what a visitor can retrieve. Authenticated routes identify the caller before making database requests. The distinction matters because opening a portfolio link should not grant access to the underlying account or its private storage paths.

02

How it works

A visitor supplies a share code and position, not an arbitrary storage path.

  • The shared profile route asks the database for the profile associated with a share code.
  • It constructs media URLs on the API instead of returning storage locations.
  • The photo route validates the requested positions and asks a database function for the corresponding path. Only then does it stream the stored file.
Read the rest

handler.ts assembles route groups, including projects and shared profiles. In lib/auth.ts, authenticate reads a bearer token and asks Supabase to validate its claims. It checks the authenticated role and the subject identifying the caller. It then creates a database client carrying that caller’s token, so database queries run with the caller’s identity available to row level security policies.

03

The hard part

I had to keep a shared profile’s external avatar from turning the server into an unrestricted downloader.

  • The avatar handler accepts only the expected image host pattern and refuses redirects.
  • It checks the response type before returning an image.
  • These checks are applied when fetching the image, even though the address was already checked when saved.
  • A response’s declared length is not enough to bound the download. The code checks the bytes as they arrive and stops when the cap is exceeded.

backend/sharing.test.ts supplies a stream whose header understates its size and verifies that reading stops. It also checks that an oversized declared length is refused before reading the body.

Read the rest

The test can observe cancellation, so it checks the behavior of the stream as well as the returned error.
