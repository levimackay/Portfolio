What it is

I wrote the contract for McKay Jewelers, then designed, built and launched the store’s website. The store is in Twin Falls. The site gives visitors a way to learn about it and plan a visit. My responsibility included the content editing setup as well as the pages people see on the public domain.

The site has home, about and visit pages, plus privacy and terms. Store information is saved separately from page content, so a phone number or hours change can reach the places that use it. The editing model matters for a store website: the owner should be able to change content without maintaining copies of the same information inside page components.

How it works

The Next.js configuration uses a static export. lib/documents.js imports saved JSON documents and pairs each with the query used by the editor. In components/live/Live.jsx, providers expose site information and page content through React context. Outside the editor they use saved data; inside it, the same components receive changing values from TinaCMS.

lib/store-facts.js turns editable store information into values the components can use. It derives a telephone link from the entered number and removes empty hours rows. It also accepts social links only when they use web address schemes. Keeping this conversion outside the components gives the tests a function they can call directly with different inputs.

The hard part

I had to keep the editor’s schema, its queries and the saved documents aligned. A field can exist in a JSON file yet never reach the editing view if the query omits it. Maintaining a separate handwritten query would leave another place to update whenever the content shape changed.

lib/queries.js builds each document query from the collection fields in tina/schema.js. Its selection function descends into object fields to include their children. tests/content.test.mjs walks the saved documents and checks that each key exists in the schema and appears in the query. The test follows nested objects too. This makes a missing field visible during verification instead of waiting for the owner to discover that an edit does not appear.

Where it stands

The site is live on the store’s domain. Cloudflare Workers serves the exported assets, and the deployment configuration points to the build output directory. There are 13 tests, covering content handling and analytics. There is no CI on this repository yet. The source is private because it is a client’s site, so there are no excerpts here.
